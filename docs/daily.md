# デイリー出題とホーム

ホームに通常表示するのはタイトル、選択日とカレンダーボタン、実線・電球・電池だけの回路アイコン1個、`play`、`how to play` だけです。カレンダーボタン1回で、大きな西暦・月・日の数字入力と月間カレンダーを同時に開きます。和暦や閉じるボタンは表示せず、枠外タッチまたはEscapeで戻れます。日付変更では生成しません。

`play` で `Loading...` の画面へ移り、既存Web Workerで検証済み問題を取得した後にゲーム画面へ移ります。二重開始はUIの切替に加えてセッション側でも拒否します。「新しい問題」「答えを表示」「home」の文字ボタンは表示せず、生成中・ゲーム・ルール説明・失敗画面のタイトルをクリックしてホームへ戻れます。ホームへ戻ると配置とタイマーはリセットされ、選択日は維持されます。

## タイマー・一時停止・クリア

問題を描画してから単調増加時計で計測を開始し、日付と同じ枠に `分:秒` を表示します。縦棒2本の記号を押すと一時停止し、盤面と置き場を隠して `Pause` だけを表示します。再開は三角の記号です。一時停止中の時間は加算せず、ドラッグをキャンセルしてキーボード操作も止めます。ページをバックグラウンドにした時間は、明示的に一時停止していなければ経過時間に含みます。

クリアするとタイマーを止め、日時・時間を囲む枠を黄色のグラデーションと静かな光で表示し、時間の下に `solved` を出します。盤面のピースは移動・回転できなくなり、置き場に代わってホーム記号と結果コピー記号のボタンを表示します。コピーする文章はタイトル・日付・所要時間・ハッシュタグのみで、SNSへの自動投稿は行いません。コピー成功・失敗をその場に表示します。

## 日付と再現性

- 初期日は `Intl.DateTimeFormat` の `timeZone: 'Asia/Tokyo'` で取得した今日。
- 日付は厳密な `YYYY-MM-DD`（西暦0001〜9999年）。端末のローカル日付解析は使いません。
- シードはUTCで計算した2000-01-01からの暦日差。整数シード0は2000-01-01、-1は1999-12-31で、異なる日付は異なるシードです。
- 初期日以外の日時は生成乱数に使用しません。日付と版の決定後は、既存の決定的な候補生成・探索をそのまま使用します。
- カレンダーの未来日を無効化し、数字入力とセッション側の検証でも未来日を拒否します。今日の上限はカレンダーを開く時、ウィンドウのフォーカス復帰、1分ごとに更新します。選択中の日付・開始済みの問題は自動変更しません。
- デイリーの選択はURLの旧 `?seed=` より優先されます（ホームはこのパラメータを使用しません）。乱数の初期化に時刻やcryptoは使いません。

端末のタイムゾーンには依存しませんが、今日の判定は端末の時計を基準とします。サーバー時刻の取得は行いません。

## 過去問の固定

`src/daily-date.js` の `DAILY_VERSIONS` は適用開始日と版の一覧です。初版は全対応日に `unique-spread-1` を割り当てています。まだWeb公開は行っていないため、この機能の導入前の日付にも初版を割り当てます。

`src/versions/unique-spread-1/` に生成器だけでなく依存する回路計算エンジンも保存しています。デイリーWorkerはこの保存版を使用し、開発用の `src/generator.js` や `src/circuit.js` の変更が出題内容に流れ込まない構成です。

将来生成器を変更する場合:

1. 過去版のファイルを編集せず、新しい版のディレクトリを追加する。
2. `daily-generator.js` の版別ディスパッチに新しい生成器を登録する。
3. `DAILY_VERSIONS` に、まだ公開されていない未来日の適用開始日を追加する。既存の過去範囲・日付からシードへの変換は変更しない。
4. 過去版のゴールデンテストを維持し、新版用のテストを追加する。

`tests/fixtures/daily-v1.json` には保存版ソースのハッシュと代表日3日分の問題JSONハッシュを保存しています。既存版や過去問の意図しない変更を検出します。将来版追加を理由にこのフィクスチャを更新してはいけません。

生成失敗時はエラー画面に移り、別シードや未検証問題への代替を行いません。同じ日付での再試行は同じ生成順序です。ホームへ戻る際はWorkerを終了し、古い応答は要求IDで無視します。

## 検証

`npm test` / `npm run build`。

追加テストでは、同日JSON一致、保存版のハッシュ、異なる日付のシードの一意性、月末・年末・うるう日・1900/2000年の扱い、日本時間午前0時の前後を確認します。UTC・Asia/Tokyo・America/Los_Angeles・Pacific/Kiritimatiを指定した別Nodeプロセスでも同じ今日・シードになることを確認します。

セッションテストでは、過去日の選択、未来日の拒否、選択時に生成しないこと、二重開始、日付をまたぐプレイ、ホームへの復帰、失敗時の同日再試行、古いWorker応答を確認します。ホームのReact出力も検査し、閉じた日付ダイアログを除くボタンが指定の3個だけで、説明文がないことを確認します。

既存の回転・ドラッグ・重なり警告・回路SVGのテストも継続します。実ブラウザでの日付ピッカーの視覚・操作確認は未実施です。
