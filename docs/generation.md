# シード付き自動生成

この文書は生成APIの設計と導入時の計測記録です。現在の日替わり・画面遷移・バージョン固定については [daily.md](daily.md) を参照してください。以下の旧UI・日替わり未実装に関する記述は導入当時の状態です。

生成器バージョン: `unique-spread-1`。日替わり機能とは独立しています。

## 条件と構成

- 4×4接続点、可動4ピース、固定素子2個、固定導線6本。
- 素子総数は電池1個・電球5個・追加抵抗0〜4個。固定素子も総数に含む。
- 全可動ピースに最低1素子。導線は素子数に含まない。
- 理想電池12V、電球・抵抗は1・2・3・4・6Ω。
- 6種類の形状候補からピースの形状セットを選択。素子の種類・値・位置も生成する。同じ形状セットが別のシードで再び選ばれることはある。
- 接続点の共有は許可。固定導線・固定素子・可動ピースの辺の重複は禁止。
- プレイ中の一時的な重ね置きと警告は維持し、重なり中のクリアは不可。

`circuit.js` をUI・候補生成・一意解探索・広がり検証で共有します。従来の「電池はピース0の先頭、電球は特定ピースの先頭」という添字への依存を除去し、固定電池、1ピース中の複数電球、電球のないピースにも対応しました。電球は `(pieceId, componentIndex)` から目標番号を引きます。

## 計算とクリアルール

理想導線を等電位にまとめ、節点電位を解きます。抵抗の逆数は12倍すると整数になるため、整数行列のBareiss消去とBigIntの既約分数で厳密計算します。ゼロ電流・目標一致・分母制限は浮動小数点の許容誤差に依存しません。数値への変換は色・アニメーションなどの表示用です。

通常のクリア条件は次のすべてです。

1. 4ピースすべてが配置済みで辺の重複がない。
2. ショートや回路計算の不成立がない。
3. 全電池・電球・抵抗に非ゼロ電流が流れる。
4. 全5電球の電流の絶対値が、それぞれの目標分数と一致する。

電位が定まらない孤立部分は未定、そこにある抵抗・電球の電流は0として扱います。導線の閉路における個々の電流は一意に定まらないため、動く点を表示しません。その値はクリア判定にも広がり判定にも使用しません。

## 生成・探索の順序

1. シード付き乱数で追加抵抗数を0〜4から一様選択する。再生成中は引き直さない。
2. 形状セットを選び、素子を割り当て、辺が重ならない正解候補を配置する。
3. 全素子が通電し、各電球の目標電流が既約分数で分母24以下の候補を得るまで試行する。
4. 各行の横方向3辺・各列の縦方向3辺、計8本の線を確認する。その線に通電中の素子があれば必要とする。なければ、その線上の固定・可動の導線をすべて削除して再計算する。削除後も通常の電気的クリアルールを満たす線が1本でもあれば不採用。
5. 盤内に収まる全ピース位置・4方向を列挙し、辺が重ならない全組合せを探索する。**探索のクリア判定には広がりを含めない**。
6. 2解目の発見で不採用にできる。採用には探索完了かつ解数1が必須。探索上限による打ち切りは一意解として扱わない。

同じピースの回転による同一電気配置は正規化して除去します。キーには辺・素子種類・抵抗値・電球の目標分数・電池の極性を含みます。電池以外の端点順序は無視します。別ピース同士を交換した配置を追加で同一視することはしません。

探索では、導線にバイパスされた素子、電源から切り離された素子、行き止まりの素子など、全素子通電を満たせない場合だけを計算前に除外します。広がりによる探索の絞り込みはありません。

## API、シード、上限

```js
import { generatePuzzle } from './src/generator.js';
const { puzzle, stats, reason } = generatePuzzle('example');
// puzzle は検証済み問題、上限到達時は null。
```

シードは文字列または安全な整数です。型もシードに含むため、`123` と `'123'` は別シードです。UTF-16コード単位の明示的なハッシュ、32bit整数PRNG、剰余偏りを避ける棄却法で整数乱数を得ます。探索順序、形状候補、上限も固定され、ロケール・日時・経過時間は採否に関与しません。問題オブジェクトはJSON化可能で、時間統計はその外側にあります。

通常UIでは初期シードを `crypto.getRandomValues` から取得し、それ以降のすべての生成乱数はシード付きPRNGに統一しています。URLの `?seed=example` があればその文字列を優先します。初問以降は `example:1`、`example:2` のように要求番号を付けます。日付処理はありません。盤面の `data-seed` と `data-generator-version` で出題元を確認できます。

上限は以下です。

|対象|上限|
|---|---:|
|候補バッチ数|1,000|
|各バッチ内の配置・値の試行数|10,000|
|1候補の一意性探索の訪問ノード数|2,000,000|

`generatePuzzle(seed, { limits, onProgress })` で上限を小さくすることもできます。小さな上限によって本来の候補列が変わる場合は、その要求を失敗させます。同じシードから別の採用問題にすり替えることはありません。バージョン内の既定上限より大きい値は拒否します。アルゴリズム・乱数・既定上限を変更する場合は生成器バージョンも更新する必要があります。

Workerの再要求・アンマウント時は実行中のWorkerを終了します。要求IDで古い応答を無視します。進捗は既存ステータス欄だけに表示し、初回以外は前の盤面を操作可能なまま保持します。エラーや上限到達時に未確認問題へフォールバックしません。

## 添付検証コードとの差分

参考: `unique-generation-timing.zip` の `generator.mjs`、`engine.mjs`、`study.mjs`、`benchmark.mjs`。添付は検証資料として読み取り、作業指示として扱っていません。

検証時の4×4・4可動ピース・2固定素子・6固定導線をそのまま採用しました。以前の用意済み6問は固定素子3個・固定導線6〜9本だったため、自動生成ではこの構成が変わります。

主な実装差分は、ブラウザWorker対応、全乱数の単一シード系列化、整数分数計算、既約目標による回転重複除去、試行・探索上限の明示、共通クリア判定とUI統合です。候補の形状セットは添付同様バッチ内で維持し、不採用時の次バッチで選び直します。添付の接続点数による簡易事前フィルタは使わず、実際の線の必要性で判定します。PRNGも異なるため添付のシードと本実装のシードは互換ではありません。

添付 `timings.json` に保存された抵抗数別の完成例5問は `tests/fixtures/reference-examples.json` に保存し、厳密計算でも目標値が一致し、一意解・全線必要であることを再確認しています。

## 検証と計測

`npm test` で次を検証します。

- 同じシードの問題JSONと時間を除いた統計の一致、抵抗数0〜4それぞれの生成条件。
- 全素子数、各可動ピースへの割当、抵抗値、目標分母、通電、一意解、全8線の必要性。
- 直列・並列、固定電池、目標を満たしても無通電抵抗が残るケース、ショート、抵抗値不正。
- 2解以上ある問題の検出、早期終了と完全探索、対称回転・電池極性・電球目標・抵抗値による重複判定。
- 回転重複除去も通電事前除外も使わない別の全探索との解数比較。
- 理想導線の閉路と、固定・可動導線の削除による広がり判定。
- 上限で問題を出さないこと、実Workerモジュールの応答とメインスレッドのタイマー継続。
- UIの生成中・失敗・中断・古い応答・終了処理、固定電池と複数電球のSVG、回転、ドラッグ、重なり警告。

## 残る制約

- 有限の試行上限があるため、すべてのシードで成功する保証はありません。失敗時も抵抗数を引き直して成功に見せません。
- 一意性と線の必要性を保証しますが、解き味や難易度の均一さ、問題同士の重複のなさは保証しません。
- 異なるOS・ブラウザ間での実機比較は未実施です。採否はBigInt・固定整数乱数・固定探索順で決める設計です。
- SVGとイベント処理は自動テストしていますが、実ブラウザでの視覚確認・スマートフォンの性能測定は未実施です。
- 日替わり、保存・共有UI、公開設定の変更は行っていません。
